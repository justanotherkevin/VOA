# Changelog

All notable changes to VOA are documented here.

---

## [Unreleased]

### Added

- **Dictation paste is now gated by a persisted, off-by-default allow-list instead of a hardcoded boolean.** A new "Paste on Complete" section in Settings → Transcription (macOS-only) lets users enable automatic paste-after-dictation and pick which running apps may receive the pasted text. The old `pasteOnComplete` flag was fully removed from the IPC surface, preload, and renderer — paste eligibility is now derived at session-end from `PastePreferences` (`enabled` + `allowedApps` string array, persisted in the app store and validated on write) and the active window's owner name via `getActiveWindow()`.
  - New `PastePreferences` schema (`src/main/store/schema.ts`) and `getPastePreferences`/`savePastePreferences` in the store (`src/main/store/preferences.ts`), with `savePastePreferences` sanitizing its input (non-boolean `enabled` coerced to `false`, non-array `allowedApps` replaced with `[]`, duplicates removed, capped at 50 entries) rather than trusting the renderer's payload.
  - New `listRunningApps()` in `src/main/active-window.ts` (macOS-only AppleScript, `osascript` with 3s timeout, returns deduplicated sorted foreground app names; resolves to `[]` on non-macOS or failure).
  - New `TranscriberService.shouldPasteForSession()` replaces the old mutable `pasteOnComplete` field — checks `type === 'dictation'`, then `PastePreferences.enabled`, then the active window's owner name against `allowedApps`. Called from `endSession()` (with `sessionStartedAt` snapshotted before the osascript await to prevent a concurrent `beginSession` from corrupting state) and `recoverLateSegment()` (for late-arriving trailing dictation segments).
  - New `pastePreferences:get`/`pastePreferences:update` and `system:list-running-apps` IPC channels (`src/main/ipc/settings.ts`), exposed in the preload as `window.electronAPI.settings.paste.{get, update, listRunningApps}`.
  - Settings UI (`src/renderer/pages/settings/TranscriptionPane.tsx`): a "Paste on Complete" section (gated on `platform === 'darwin'`) with an enable toggle, a "Refresh" button that re-runs `listRunningApps()`, and a checkbox list rendering the union of running apps and previously-allowed apps so a checked app stays visible even when not currently running. `listRunningApps()` is fetched in parallel with other pref loads in `Settings.tsx`'s `loadAllPrefs` to avoid blocking cache/LM Studio/calendar fetches behind the osascript call.
  - Removed dead `pasteOnComplete` from `beginSession()`'s signature, `SESSION_START`'s IPC args, the preload's `startSession` options type, `useRecordingFlow.ts`'s `handleToggleCapture`/`handleToggleDictation`, `lastSessionMeta`, and `transcriberTestHelpers.ts`'s `resetTranscriberSessionState()`.
  - Tests: `active-window.test.ts` (3 tests for `listRunningApps`), expanded `transcriber-integration.test.ts` (7 paste-allow-list tests replacing the old `pasteOnComplete` tests, covering: enabled/disabled, allowed/not-allowed app, undetected window, empty transcript, meeting-type sessions, late-segment recovery, no double-paste), `transcriberService.test.ts` (missing mocks added), `Settings.test.tsx` (asserts paste section renders), and `electronMocks.ts` (new `settings.paste` mock surface).

- **The notification window now shows a "loading" state while the transcription model warms up, instead of gating recording behind a silent wait.** `TranscriberService` broadcasts idle/loading/ready/error model-load status over a new `transcriber:model-status`/`transcriber:model-status-changed` IPC pair (`getModelStatus()` IPC handler + `setModelStatus()`/`initializeWithStatus()` in `src/main/services/transcriber.ts`), replacing the old renderer-side inference from ad-hoc `initiate`/`ready` transcriber events.
  - New `useModelStatus` hook (`src/renderer/hooks/useModelStatus.ts`) subscribes to the broadcast, drives the model-load toast, and exposes `ensureReady()` so callers can await a warm model.
  - `useRecordingFlow` now shows the new `'loading'` notification state (`Notification.tsx`, `useNotificationFlow.ts`) before a cold-start recording begins, and only shows the "recording" notification once the model reports ready; a warm model skips the loading flash entirely.
  - `AppStatus` (sidebar status dot) moved from `Sidebar.tsx` to `useRecordingFlow.ts` and is now `idle`/`recording`/`loading` (previously `ready`/`recording`/`processing`), driven by the same model-status signal.
  - `useTranscriber.ts`'s old `isModelLoading` flag and the `initiate` IPC channel/listener were removed; `AIModel.tsx` (already-unused, superseded by `pages/settings/TranscriptionPane.tsx`) was updated to type-check against the removal but is otherwise dead code.
- **The public landing page now has real technical and on-page SEO.** `docs/index.html` gains a canonical link, a favicon (`docs/favicon.svg`, copied from `assets/icon.svg`), a `theme-color` meta tag, Google Fonts `preconnect` hints, and a `SoftwareApplication` JSON-LD block (no fabricated ratings/reviews). `docs/robots.txt` and `docs/sitemap.xml` were added so the site is crawlable. The hero H1 was rewritten from "Meeting transcript, summary, action items. without wifi." to three keyword-bearing sentences ("Offline meeting transcription for Mac.", "Transcript, summary, action items.", "No cloud, no account."), the `<title>`/description/OG/Twitter tags were tuned to match, the smart-summary screenshot's `alt` text was fixed (it previously described a different screenshot), and the hero `<video>` got `preload="metadata"`.

Inputs have visually-hidden `<label>`s for accessibility.
- **Meeting titles now use the matched calendar event's plain title instead of a raw `[Meeting] ...` transcript snippet.** `CalendarEventMatch` (`src/main/pipeline/types.ts`) exposes a plain `summary` alongside the time-suffixed `title` used for the calendar-match picker; `TranscriberService.persistMeeting()` resolves the title as: confirmed calendar match's summary → `"Meeting with Alice"` / `"...Alice and Bob"` / `"...Alice, Bob, and N others"` (`formatParticipantsTitle()` in `src/main/store/migrations.ts`) when participants exist but there's no match → `"Untitled Meeting"`. Dictations are unaffected and keep the transcript-derived title.
  - Added first-letter participant avatars (stable per-participant hashed colors, `src/renderer/utils/AvatarUtils.ts`) to the sidebar meeting list row and the meeting detail key-facts panel, replacing the old "Participants: N" text fact.
- **Onboarding now actually runs on first launch, and downloads both AI models before letting you in.** The `/onboarding` route already existed but nothing ever navigated to it and no completion flag was stored, so new users never saw it.
  - A new `onboardingCompleted` preference (`src/main/store/schema.ts` + `preferences.ts`, `onboarding:getCompleted`/`setCompleted` IPC) is written when the user leaves onboarding; `App.tsx` picks the router's initial route from it. Under `E2E_TEST` the getter reports `true` unless `E2E_ONBOARDING=true`, so existing e2e specs don't boot into the flow.
  - A new **Models** step (Permissions → Models → See It Work) shows two progress bars: the built-in Qwen2.5 1.5B GGUF summarization model and Whisper Base. Continue is disabled until both finish, and each bar retries independently so a failed download never leaves only a dead button.
  - Whisper Base is downloaded via the existing `modelPreferences:update` path, so it also becomes the selected transcription model for new installs (previously Tiny). Progress is aggregated across files, since transformers.js reports per file rather than overall.
  - Bars start in a "Checking…" state rather than at `0%`, which otherwise made an already-downloaded model look like it was downloading from scratch.
  - Onboarding continues to use the built-in embedded LLM — it does not ask users to install LM Studio.

Pressing it starts/stops a capture forced to `type: 'dictation'` (skipping meeting-app detection) and, on completion, pastes the transcribed text into the active window. Rebindable from Settings → Shortcuts via the existing `ShortcutConfigDialog.tsx`, now generalized to configure either binding.

### Fixed

- **The app icon looked oversized and blurry in the macOS Dock next to other apps.** `assets/icon.png`'s artwork filled 100% of its canvas edge-to-edge, unlike the ~80.5% squircle-with-margin grid every other macOS icon follows, and `app.dock.setIcon()` (`src/main/main.ts`) was sourcing from a 64px asset the Dock then upscaled 4x. The artwork is now padded to the standard grid and the Dock icon is set from the full 512px asset; `assets/icon.icns` and the unused ERB-default `assets/icon.svg` were removed since electron-builder derives `.icns` from `icon.png` and nothing referenced the SVG.
- **The collapsed sidebar's app icon overflowed its header padding and sat visibly off-center**, unlike the Settings button below it, which fit its collapsed rail exactly. `SidebarHeader`'s `px-1` narrowed the icon's box to 24px while the `<img>` was sized at 32px (`w-8`) with `shrink-0`, so it spilled 8px to the right. Resized to `w-6 h-6` (24px) to match the box; also dropped a `rounded-lg` class that was clipping tighter than the artwork's own baked-in corner radius, making the icon look rounder than designed.
- **Sidebar became unusable with a large meeting history — the meeting list overflowed the whole sidebar and pushed Settings off-screen entirely**, since the list had no bounded scroll region of its own. Fixed by making `SidebarContent` the sidebar's one `flex-1 min-h-0 overflow-auto` region; `SidebarHeader`/`SidebarFooter` are fixed-height siblings, so Settings now always stays visible regardless of meeting count (verified with 35 seeded meetings).
- **Clicking "Settings" (or "Meetings") repeatedly could leave its list unexpectedly collapsed** — the row was originally a single button that both navigated and toggled the collapsible open/closed, so revisiting it an even number of times left it closed. This made e2e flows that navigate to Settings more than once per run (`shortcuts.spec.ts`, `system-audio.spec.ts`) flaky/timing out. Split into two controls: the row itself always navigates and forces the section open; a separate chevron button toggles collapse independently.
- **Dual-source (mic + system audio) recordings could save with the wrong `audioSource` and no `[Mic]`/`[Meeting]` tags** — the trailing VAD mic segment flushed on stop could arrive after `session-end` had already closed and saved the meeting, since `useRecordingFlow.ts`'s session-end effect only waited on `transcriber.isBusy` (never set in VAD mode). It now also waits on a new `hasPendingVadSegment` signal (`useVAD.ts`, `useAudioRecorder.ts`) before ending the session. As a safety net, `TranscriberService.recoverLateSegment` (`src/main/services/transcriber.ts`) now tags a late segment and upgrades `audioSource` to `'both'` if its source still slips in after the fact.
- **Model-load toast getting stuck on "loading" forever** — the Settings-save IPC handler (`src/main/ipc/settings.ts`) only returned an error in its response but never broadcast `transcriber:error`, which is what actually resolves the renderer's toast. It now broadcasts `transcriber:error`/`transcriber:ready` on the outcome, matching the app-startup preload path.
- **Base/Small/Medium remained selectable in Settings despite being marked disabled** — the live Settings page (`src/renderer/pages/Settings.tsx`) has its own inline model list that never checked the `disabled` flag; a since-unused `AIModel.tsx` component had the correct logic but isn't rendered anywhere. `Settings.tsx`'s model list and `updateModelPref` now check `disabled` and revert optimistic UI state on a failed update instead of silently ignoring it.
- **`notification-visibility.spec.ts`'s recording-state test only checked that a static container div was attached**, not that the actual "recording" state text rendered — passed even when the toggle silently failed to reach the renderer. Now asserts the real text is visible.
- **A second concurrent system-audio capture starved the real transcription capture, producing a bare `"[ Pause ]"` transcript instead of real speech.** The new dual mic + system-audio waveform on the "Recording" notification pill opened its own `electron-audio-loopback` tap purely for level metering, alongside the real capture already running for transcription — on macOS this is a single OS-level audio tap, so the second one stole it. The waveform now meters levels off the same stream used for real transcription (`src/main/preload/audioCapture.ts`) and forwards them to the notification window over IPC (`system-audio:levels`, relayed in `src/main/ipc/notifications.ts`) instead of opening a second tap.
- **Meetings started via the plain recording shortcut (F1) could be misclassified as `type: 'dictation'`** whenever the focused window wasn't on the meeting-app detection list, landing them in the Dictations list instead of Meetings. `ipc/transcriber.ts`'s `SESSION_START` handler no longer guesses intent from the active window — that predates the dedicated dictation shortcut (F2); an unforced session is now always `'meeting'`, and only `forceType: 'dictation'` (from the dictation shortcut) opts into `'dictation'`.
- **The recording shortcut could stop a session started by the dictation shortcut (and vice versa)**, cutting off the wrong capture mid-session. `useRecordingFlow.ts`'s toggle handler now only stops a session if the incoming shortcut matches the session's actual type; the mismatched shortcut shows an informational toast instead of stopping the wrong capture.
- **`model-switch-toast.spec.ts` could fail when a prior spec left a recording session active**, since `settings.ts`'s model-update handler rejects outright while a session is running. Added an e2e-only `transcriber:e2e-session-active` check (`transcriber.e2e.ts`, `preload.ts`) so the spec can detect and clear a leaked session before asserting on model-switch behavior.
- **`triggerNotificationShow` (the notification test mock, `src/testing/electronMocks.ts`) hardcoded `state: 'recording'` regardless of the title passed in** — two "Recording Stopped" tests in `notification.test.tsx` were showing that title while the component silently stayed in the `recording` state (waveform included) the whole time, so they never actually exercised the recording-stopped UI. The mock now takes an optional `state` param, and the affected tests pass it explicitly.
- **`useRecordingFlow.ts`'s done-transition effect ended a session's UI state on a fixed 300ms timer without waiting on the real `endSession()` IPC round trip**, so a newer session's own state could get stomped if it started while a prior session's backend teardown (VAD flush + `persistMeeting`) was still in flight. The effect now awaits `endSession()` before touching UI state, and cancels its own continuation (instead of the old timer) if superseded by a newer session.
- **`meetingDetector`'s real active-window polling stayed running during E2E test runs**, so it could auto-start a genuine, unmocked recording session mid-suite whenever the actual foreground app on the machine running the tests happened to match a monitored meeting app — a source of nondeterministic leaked-session failures unrelated to any spec's own actions. It's now disabled when `E2E_TEST=true`.
- **`notification-visibility.spec.ts` and `model-switch-toast.spec.ts` cleaned up a leaked recording session with a short fixed wait and always sent the plain recording toggle**, which could miss a still-tearing-down session (real teardown can take longer than a couple of seconds under load) or fail to stop a session actually started via the dictation shortcut (`useRecordingFlow.ts` ignores a mismatched toggle type). Both specs now poll for real teardown (up to 25s) and send the toggle matching the leaked session's actual type.
- **Whisper's decoder could loop on a repeated phrase verbatim.** `whisper-process.ts`'s transcription call now sets `repetition_penalty`/`no_repeat_ngram_size` to guard against the decoding-loop hallucination.

### Known issues

- **A real recording session started before `useVAD.ts`'s `MicVAD.new()` finishes loading can leak a duplicate, full-audio transcription completion.** `useAudioRecorder.ts`'s `handleDataAvailable` closure captures `vadInitialized` at the moment `startRecording()` was called rather than reading a live ref; if VAD is still loading at that instant, the closure keeps a stale `false` for that `MediaRecorder` instance's whole lifetime, so its trailing stop event skips the "VAD is handling this" guard and fires a second, redundant completion job against the shared transcriber queue. Diagnosed via a live Electron run (confirmed with temporary logging, since reverted) as the source of an intermittent leaked-session failure surfaced by the e2e suite; not yet fixed.

## [1.0.0] — 2025

Initial public release.

### Added

- **On-device Whisper transcription** via `@xenova/transformers` + ONNX Runtime (Tiny, Base, Small, Medium models)
- **Voice Activity Detection** using `@ricky0123/vad-web` — automatically segments speech from silence
- **Smart meeting detection** — detects active calls in Zoom, Teams, Google Meet, and Slack via Accessibility API
- **AI-generated meeting summaries** and structured action items using Qwen2.5-1.5B-Instruct (local)
- **Meeting vs. monologue distinction** — classifies recordings based on whether another participant was detected
- **Global keyboard shortcut** — start/stop recording from any app (configurable, default F1)
- **Always-on-top recording pill** — floating notification showing waveform and in-meeting prompts
- **Structured meeting detail view** — sidebar-split layout with transcript and AI summary side by side
- **macOS-style settings UI** — System Settings-inspired interface with 7 panes:
  - General (theme, accent color, density, startup)
  - Recording (auto-record modes, meeting app detection)
  - Audio (mic source, gain, noise suppression)
  - Transcription (model selection, download/cache management)
  - Shortcuts (configurable hotkeys)
  - Privacy & Storage (data management)
  - Permissions (Microphone, Accessibility, Screen Recording)
- **Privacy-first architecture** — zero cloud dependency; no account, no telemetry, no data transmission
- **Local model caching** — models downloaded once and cached; configurable via settings
- **Audio retention policy** — raw audio kept 3 days post-recording for diarization; transcripts kept indefinitely
